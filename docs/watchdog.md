# A1 / M1 硬件看门狗

A1、M1 共用 `common/watchdog.c`。应用启动即初始化 MX1290 硬件 WDG，只允许专用监控线程喂狗。SDK 自带系统监控保持关闭：它的线程超时路径调用软件重启，无法保证硬件 watchdog 复位原因。构建补丁用 `PHICOMM_APPLICATION_WATCHDOG` 移除板级默认的 `MICO_DISABLE_WATCHDOG`，冲突配置直接编译失败。

## 心跳与超时

| 槽 | 完成工作的线程 | 超时 |
| --- | --- | --- |
| hardware | A1 风扇、触摸与灯环共用工作循环；M1 UART、传感器与屏幕工作循环 | 10 秒 |
| binding | 联动、定时与局域网处理循环 | 10 秒 |
| network | 网络管理、配网与配置保存循环 | 30 秒 |
| ota | 当前同步 OTA 处理阶段，有进度时续期 | 30 秒 |

硬件超时 3 秒；监控线程优先级 0，每 500 毫秒检查一次。启动必须在 60 秒内完成初始化并收到全部关键线程心跳；每个线程首次报告后即使用其正常超时。监控读取时间和心跳、判定和喂狗位于同一短临界区；mocOS 没有实现其声明的 MiCO 临界区接口，因此在 ARM 上使用保存/恢复 PRIMASK 的临界区。

任意到期都会不可逆地锁存故障并停止喂狗。迟到的心跳、OTA 进度或操作结束不能恢复喂狗。正常调度时，硬件复位预计发生在最后有效心跳的业务超时后约 3 秒内；精确时序需实机测量。调度器或监控线程本身停止时，最后一次喂狗后由硬件超时复位。监控及故障路径不获取业务互斥锁，不分配内存、不写 Flash、不记录日志。

心跳表示工作循环取得进展。Wi-Fi/MQTT 断线、无传感器采样、外设返回错误均不是超时；A1 GPIO 初始化与 M1 UART 初始化失败会报告错误、定期重试并报告心跳。外设调用不返回或关键循环死锁仍会超时。未把 HTTP/MQTT 工作线程单独列为必需心跳。

## 正常长操作

NTP 的同步调用有一次最多 180 秒的 network 专用宽限；重复开始和普通心跳不能延期，返回后恢复 30 秒。宽限不影响 hardware、binding。A1 的 `feature_clock_tick` 与 M1 首选/回退校时共用此约束。

OTA 每次同步 begin-unsigned、write、finish 期间激活独立进度槽。网络接收等待不计作 OTA 工作超时；原有下载期限继续生效。OTA TEMP 按 4 KiB 扇区擦除，写入、校验读取每块不超过 512 字节，块间休眠 1 毫秒让业务线程运行。只有监控线程能喂硬件狗，OTA 的进度不替代其他必需心跳。签名、产品身份、CRC、MD5、回读校验以及最后提交启动信息仍执行；错误路径关闭本次 OTA 进度槽。

板级 Flash 扇区擦除及单块写入必须在硬件的 3 秒期限内返回；这需要在目标设备测量。此实现不通过停止硬件 WDG 或全局延长心跳来绕过慢操作。

## 复位提示

启动缓存 SDK `get_last_reset_reason()` 位掩码：低三位电源事件，`0x08` 软件，`0x10` lockup，`0x20` watchdog；未知值保留原始数值。硬件 watchdog 原因优先于其他位。串口及 RAM 启动日志记录原因；Web 诊断显示原始值和“上次因看门狗超时重启”。API 字段见 [WebUI 约定](webui-contract.md)。故障槽不跨复位持久化，避免超时路径依赖 Flash。

## 验证

主机回归：`tests/run.sh` 编译实际公共监控实现，覆盖逐个线程缺失、超时锁存、启动期限、32 位时钟回绕、NTP 宽限、OTA 进度与其他线程隔离、擦除块进度、复位原因、初始化和监控线程创建失败。`tests/ota/run.sh` 验证签名协议，并使用构建的 A1/M1 原生镜像运行实际 OTA 核心；可用 `A1_TEST_IMAGE` / `M1_TEST_IMAGE` 指定镜像，缺少镜像时对应适配器用例会跳过。CI 下载两款构建镜像并要求其存在。

前端仓库的 `node tests/test_web.cjs` 验证 A1/M1 提示与 TC1 兼容；`./A1/build.sh`、`./M1/build.sh` 验证 SDK 补丁、实际 ARM 实现和链接。

实机验收需使用可恢复的专用测试固件并明确设备与刷写授权，本实现不提供生产远程故障注入接口。以下场景尚需在目标设备执行：

1. 分别冻结 hardware、binding、network，记录最后心跳至复位时间，重启后核对 SDK 原因和网页提示。
2. 暂停监控线程、阻塞调度或关闭中断，确认无其他喂狗来源且硬件能够独立复位。
3. Wi-Fi/Broker 长时间离线、传感器或面板断开时保持运行，恢复连接或外设后业务可恢复。
4. NTP 全部失败、首选域名解析超时；允许正常回退完成，超过宽限则复位，其他线程在宽限内卡死仍应复位。
5. 文件/HTTP 签名 OTA，测量最慢扇区擦除及块写入/回读时间，观察关键业务调度；验证成功重启、镜像损坏、擦写失败和下载中断。OTA 过程中冻结业务线程仍应 watchdog 复位。
6. 冷启动、软件重启及 watchdog 重启，确认原因区分正确；长时间运行监测误复位。

主机模型和编译不能证明硬件超时精度、闭源 MOC 内核行为或真实 Flash 最坏耗时。
