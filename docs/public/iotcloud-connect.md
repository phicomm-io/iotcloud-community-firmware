# 接入 IoTCloud

IoTCloud 是 TC1 智能排插、M1 与 DAIKIN 空气检测仪、A1 空气净化器的网页管理平台。设备接入后，可以在同一个页面查看在线状态、空气读数与排插功率，并远程使用设备支持的控制和设置。账号模式会保存设备列表，换手机或电脑登录同一节点、同一账号即可继续管理。

[打开 IoTCloud]({{SITE_URL}}iotcloud/) · [先体验模拟演示]({{SITE_URL}}demos/platform/)

## 1. 准备设备与账号

设备需已安装本项目固件、完成 Wi-Fi 配网，并能通过局域网 IP 打开本地网页。初次安装见[快速开始](quick-start)。配置时，手机或电脑应能访问设备所在的局域网；远程管理时，设备与浏览器都需要能连接所选平台节点。

打开 IoTCloud，在顶部选择 China 或 US，再点击“注册账号”。按页面要求设置用户名和密码；需要邮箱验证时，填写邮箱并获取验证码。注册关闭时，按页面提示联系管理员。

| 节点 | 网站入口 | 设备 Broker 地址 | 设备 MQTT 端口 |
| --- | --- | --- | --- |
| China · 中国 | [mqtt.fjrcn.cn](https://mqtt.fjrcn.cn/) | `mqtt.fjrcn.cn` | `1883` |
| US · 美国 | [mqtt.fjrcn.com](https://mqtt.fjrcn.com/) | `mqtt.fjrcn.com` | `1883` |

**两个节点的账号、密码、设备和数据独立，需要分别注册。** 请在注册、登录和设备配置时使用同一节点；切换节点不会迁移设备。

登录后，进入“设置 → MQTT 连接”，选择“平台 Broker”，确认平台显示“已连接”。默认自动连接；如果此前手动断开过，点击“连接服务器”。

> MQTT 初始密码为注册时设置的密码。之后，网站登录密码和 MQTT 密码可以分别修改：修改网站密码不会改变 MQTT 密码；修改 MQTT 密码后，需要更新浏览器连接设置和所有设备中的 MQTT 密码。设备本地网页密码也不用于 MQTT 登录。

## 2. 将设备连接到平台

以下两种方式任选一种，使用相同的 Broker 和账号配置。

### 方式一：手动填写

1. 在浏览器打开设备的局域网 IP，按需输入设备网页密码。
2. 进入“网络 → MQTT / Home Assistant”，在 Broker 表单中填写：

   | 字段 | 填写内容 |
   | --- | --- |
   | Broker 地址 / MQTT Host | 所选节点的主机名，例如 `mqtt.fjrcn.cn` |
   | 端口 | `1883` |
   | 用户名 | 在所选节点注册的平台用户名 |
   | 密码 | 当前 MQTT 密码，初始为注册密码 |
   | 主题模式 | TC1 在“高级”中选择 **TMCP（v2）**；M1、A1、DAIKIN 固定使用 TMCP |

3. 点击“保存”，等待设备 MQTT 状态变为已连接。更改后若设备仍在重连，先核对地址、账号和密码。

**设备 Broker 地址只填写主机名，不带 `https://`、`wss://` 或 `/mqtt`。** `https://phicomm-io.github.io/iotcloud/` 是网页入口，不能作为设备 Broker。浏览器使用的 `wss://mqtt.fjrcn.cn/mqtt` 或 `wss://mqtt.fjrcn.com/mqtt` 也不能填入设备 Host。

### 方式二：从平台预填到设备

1. 使用能访问设备局域网的手机或电脑，进入 IoTCloud 的“设置 → MQTT 连接”或“设备管理”，点击“填写到本地设备”。
2. 输入设备 IP 或本地网址，核对 Broker 主机名、TCP 端口 `1883`、平台用户名和当前 MQTT 密码，确认设备地址后点击“打开设备并填写”。
3. 在新打开的设备页面核对发起平台的来源，点击“接收并预填”；设备设有网页密码时仍需正常验证。
4. 检查预填内容，点击设备页面的“保存”，再确认 MQTT 已连接。平台提示“已预填”仅表示内容已送到设备网页。

请保留平台窗口，并在两分钟内完成接收。仅向已核对的设备地址、在可信局域网内发送。浏览器拦截弹窗、接收过期或设备 WebUI 不支持此功能时，改用手动填写。

## 3. 确认设备上线

回到同一节点的 IoTCloud。使用相同 MQTT 账号的 TMCP 设备会自动出现在列表中；等待列表刷新，也可进入“设置 → 设备管理”点击“刷新”。

如果仍未出现，先检查设备本地 MQTT 状态。也可在“设备管理 → 添加设备”填写本地网页显示的 **MAC 地址**、正确型号和协议。MAC 为 12 位十六进制字符，也接受冒号或短横线分隔。手动添加只登记设备，不会替设备配置 MQTT。

- **TC1**：本项目固件推荐 TMCP；Legacy（v1）仅用于实际使用旧协议的 TC1，需手动添加。
- **M1、A1、DAIKIN**：选择对应型号，协议固定为 TMCP。

确认平台 MQTT 显示“已连接”、设备卡片显示“在线”，并且读数持续更新。可以打开详情检查 M1 的实时读数，或调整 M1 屏幕亮度后在设备上核对；其他设备按实际需要检查相应功能。完成接入后，手机切换到移动网络仍可通过平台访问在线设备，无需给设备配置公网端口映射。

DAIKIN 详情显示独立的 PM2.5 / PM10 卡片、CO₂、温湿度与 TVOC 舒适度条；TVOC 建议参考为 ≤300 ppb。未安装甲醛模块时不显示甲醛卡片，联动设备区域显示实际已读取的 A1 会话。

日常操作见 [TC1](tc1-guide)、[M1](m1-guide)、[A1](a1-guide)、[DAIKIN](daikin-guide)；A1 的数据源授权和自动联动按 [MQTT 与联动](mqtt-link)单独配置。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 能登录网站，但平台 MQTT 未连接 | 在“设置 → MQTT 连接”选择平台 Broker，检查当前 MQTT 密码并点击连接；网站登录成功不代表 MQTT 已连接 |
| 平台已连接，设备仍离线 | 查看设备本地 Wi-Fi、MQTT 状态，核对 Broker、`1883` 端口、节点账号和当前 MQTT 密码；确认设备能访问互联网 |
| 没有自动发现设备 | 确认双方使用同一节点、同一 MQTT 用户名；TC1 选择 TMCP。Legacy TC1 需手动添加 |
| 手动添加后仍离线 | 核对 MAC、型号与协议，并确认已在设备本地保存 MQTT 配置 |
| 改密后无法连接 | 区分网站密码与 MQTT 密码；更改 MQTT 密码后同步更新浏览器和所有设备 |
| 切换节点后设备列表为空 | 两个节点各自保存账号和设备；返回原节点，或在新节点注册后重新配置设备 |
| 连接自己的 MQTT 服务器 | 使用“自建 Broker / 访客模式”，填写支持 WebSocket 的地址；该模式的列表与平台账号模式独立 |

如需自行托管网页、账号服务或 Broker，见 [IoTCloud 部署](iotcloud-deploy)。
