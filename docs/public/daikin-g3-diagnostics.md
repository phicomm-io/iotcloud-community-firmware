# G3 启动、资源与显示诊断

本页对应[当前 RC6 下载]({{SITE_URL}}#releases)。先在设备信息中确认 ESP32 版本、屏幕 MCU 版本、资源状态和运行时间。安装与恢复步骤见[主指南](daikin-g3-guide)，原厂组件见[备份文档](stock-backups)。

## 启动与维护窗口

屏幕先启动通信与恢复服务，ESP32 默认在 5 秒后继续业务；可关闭自动继续，保留 30 秒最小服务窗口。“保持最小服务”优先于自动继续，“立即继续启动”可提前结束窗口。故障维护不会自动退出。字库与传感器启动时显示加载动画，单项失败限时结束等待。

完全断电后，原厂引导的开机门控仍可能要求短触正面按键。本版本不修改引导区来实现来电自动开机。普通短触翻页，背面孔内按键用于网络功能，不应当作通用复位操作。

更新 MCU 时临时降低到 10% 亮度，并控制 AM1008L 的 PD12 SET 为低；业务准备完成后恢复。软件诊断拉低最长 60 秒，超时自动恢复，不保存成永久关机配置。维护和升级期间由独立互锁保持模块关闭。

出现黑屏或重启时，分别记录 ESP32 与 MCU 的运行时间/复位原因、供电状态和模块是否连接。屏幕黑屏不等于 ESP32 断线；网页在线也不等于屏幕业务已启动。先固定供电和接线做对照，避免反复带电插拔。

## 资源与缺字

完整 32 px 中文字库位于外部 SPI NOR，校验后缓存到 SDRAM。启动先显示内置精简字体，后台加载完成后刷新。“广州”等自定义汉字若临时显示占位符，查看字库状态与进度；仅设置城市标签不会自动下载字库。

NOR 硬件读取、分批校验和备用路径均有限时。读取失败可退回 GPIO；资源不可用时降级到内置字体、缺字占位与纯色背景，通信、传感器和 OTA 继续运行。不要用无限重启处理资源错误。字库和壁纸独立于 MCU 应用更新，正常应用 OTA 无需重复上传。

## ESP32 内存与天气

“总空闲”包含只能按 32 位访问的 IRAM，TLS 和常见网络缓冲需要可逐字节访问的内部 DRAM。检查可用字节堆、最大连续块和最低水位，不能用总数判断天气一定能启动。

RC6 释放空闲时的 6 KiB 状态编码临时区，发送结束后释放延迟串口消息缓冲。9520 字节的 SCN3 串口缓存优先使用空闲的 32 位 IRAM，以对齐字访问；不可用时回退 DRAM。布局编码和上传缓冲按需申请、完成或超时后释放。

`screen.status` 的 `layout_cache_bytes`、`layout_cache_storage` 显示缓存长度与 `iram` / `dram` / `unallocated`。`screen.weather.get` 显示字节堆、最大块、worker 前后水位、尝试次数、连续失败与重试时间。Open-Meteo 当前准入需要 72 KiB 字节堆和至少 24 KiB 连续块，其他提供商需要 84 KiB；总空闲 100 KiB 仍可能不满足。内存失败会退避，保留旧缓存。

这些优化已通过构建与主机检查；IRAM 实际落点和天气恢复仍以更新后的设备状态为准。暂停天气和避免并发大文件操作可作为低负载对照，不替代内存指标。

## 换页测量

进入“屏幕 → 诊断”，选择当前页、指定页或下一次换页；触发换页后读取并导出记录。支持 MCU 才显示此入口。每次采集最多 96 条记录，分批每次读取 8 条；整次报告需同一个 generation，并检查丢弃计数。

| 指标 | 含义 |
| --- | --- |
| 扫描周期 | LCD 帧结束中断统计的周期，包含中断延迟，不是示波器测得的引脚波形 |
| flush 区域、次数与耗时 | 同步刷新时包含实际像素拷贝；记录区域坐标和最后一块标记 |
| monitor 次数、像素与时间 | LVGL 每轮绘制刷新，换页可能涉及多轮 |
| 相邻 flush 间隔 | 包含绘制和调度，不能直接解释为等待 VSYNC |

现有驱动为单份扫描帧缓冲与 40 行绘制缓冲，完整页面通常 22 次拷贝，代码未逐块等待 VSYNC。2026-11-07 的一组保存布局测量约 40 Hz 扫描、613～693 ms LVGL 刷新、约 141 ms 总拷贝；这些是特定布局的历史对照，不是所有页面的性能保证。

原厂驱动使用两份完整缓冲并在帧边界装载显示地址。后续优化需分别验证纯色、预解码图片和完整页面，确认独立 A/B 地址、未改区域同步、切换超时及 OTA 响应，再评估 DMA2D。现版本的诊断本身不改变扫描时钟或启用双缓冲。详见[开发资料](daikin-g3-development)中的显示诊断与换页性能报告。
