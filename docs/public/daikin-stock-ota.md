# 大金 BRY88AB151K：通过原厂 OTA 刷入社区固件

本教程使用原厂的局域网升级服务，将标准 ESP32 应用镜像传给设备，不需要为原厂 OTA 单独构建一种镜像。2026-10-24 已在 **BRY88AB151K、原厂 SV.02.00.01.15、4MB Flash** 上完成按键触发、上传和社区固件启动验证。

**适用范围仅限上述实测型号和原厂版本。BRY88AX151K、其他原厂版本不能直接套用这份镜像。** 本次实测先用串口备份并恢复了原厂，再执行无线迁移；证明的是按键和 OTA 通道可用，未覆盖所有出厂配置状态。教程提供的镜像是实测的 `0.9.21-2cfd89-dirty` 测试构建，不代表当前稳定发行版。

## 1. 原理与准备

原厂在进入升级模式后开放 TCP 8555 服务。电脑连接设备热点，通过专用发送器完成握手、版本检查、分块传输和校验。成功后，设备把启动分区切换到备用槽，再重启运行社区应用。

准备以下物品：

- 一台型号与原厂版本匹配的大金设备，使用稳定的正常电源供电。
- 能连接 2.4GHz Wi-Fi 的 Windows、macOS 或 Linux 电脑，以及 Python 3。发送器只使用 Python 标准库，不需要安装第三方 Python 包。
- 配套发送器、应用镜像及其 SHA-256。先在电脑仍能上网时下载。
- 对应设备的恢复条件。建议首次尝试前经串口保存自己的完整 4MB Flash 备份；不要下载别人的完整备份覆盖设备身份和私人配置。

电脑可以用有线网络上网、Wi-Fi 连接大金；只有一张无线网卡也可以，文件下载完成后切换到大金热点即可。刷机期间电脑不必能访问互联网。

**进入原厂 OTA 模式就会初始化并擦除备用应用槽，并非等开始上传才擦除。** 传输和切换期间不要断电。GPIO0 接地用于串口下载，本教程操作的是配网键对应的 GPIO34，两者不要混淆。

## 2. 下载配套文件

- [下载 Python 发送器](assets/tools/daikin-stock-ota/daikin_stock_ota.py)
- [下载实测 BRY88AB151K 应用镜像](assets/tools/daikin-stock-ota/daikin-bry88ab.application.bin)
- [下载 SHA256SUMS](assets/tools/daikin-stock-ota/SHA256SUMS)

把两个文件保存在同一个文件夹。镜像大小应为 **1,027,296 字节**，SHA-256 为：

```text
649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e
```

使用的是普通 `application.bin`，本次没有重编译或修改它。不要改用 `factory.bin`、整片 Flash 备份、带签名外壳的升级包或其他机型的镜像。原厂每个应用槽只有 **1,572,864 字节（1.5MiB）**，此限制在首次迁移后仍然保留。

先打开文件所在目录的终端，仅校验文件，不连接设备：

Windows PowerShell：

```powershell
py -3 .\daikin_stock_ota.py .\daikin-bry88ab.application.bin --sha256 649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e --check-only
```

macOS / Linux：

```sh
python3 ./daikin_stock_ota.py ./daikin-bry88ab.application.bin --sha256 649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e --check-only
```

如果提示找不到 Python，先安装 Python 3；如果哈希或镜像格式不匹配，停止并重新下载，不要跳过检查。

## 3. 用按键进入原厂 OTA

设备正常上电、运行原厂程序后，在配网键上连续执行：

1. 按住约 **3 秒**，松开约 **0.5 秒**。
2. 再按住约 **3 秒**，松开约 **0.5 秒**。
3. 再按住约 **3 秒**，松开。

每次长按需要落在约 2～5 秒之间，每次松开到再次按下的间隔不要达到 2 秒。不要把三次合成一次长按，也不要每次按到 5 秒以上。本次这套手势已实测触发 `mode 0` OTA 任务。

**原厂某些配网状态下，长按会恢复配置并重启，而不是累计 OTA 手势。** 已知判断与原厂内部 `wififlag` 有关，不能把这套操作当作所有状态都不会清配置的手势。若设备重启或手势没有生效，先观察状态，不要反复延长按压时间。

有串口观察条件时，成功日志包含：

```text
Start OTA Task Suceess, mode 0
app_ota_server_create success
```

无线操作不要求连接串口；串口日志是排查手势失败的方法。

## 4. 电脑连接原厂热点

在电脑 Wi-Fi 列表中找到 `daikin!` 开头的设备热点，输入原厂此版本的默认热点密码 **`12345678`**。

本次实测热点名为 `daikin!f76748f9`。每台设备后缀可能不同，不要照抄示例名称。优先对照自己设备的 MAC；实测设备 STA MAC 为 `9c:9c:1f:f7:67:48`，对应热点 BSSID 为 `9c:9c:1f:f7:67:49`。

连接后，实测电脑通过 DHCP 获得 `192.168.4.2/24`，网关与设备地址为 **`192.168.4.1`**。系统提示“无互联网”属于正常现象，请保持连接。不要继续使用刷机前设备在路由器中的旧 IP；检查电脑是否自动切回其他 Wi-Fi。

Windows 推荐直接通过系统 Wi-Fi 菜单连接。若用 `netsh` 在远程 SSH 会话中连接，本次发现 current-user profile 会返回 `0x57`，改用该热点的 all-users profile 才成功；不要为此删除其他网络的配置。

## 5. 上传应用镜像

确认当前连接的是自己的大金热点，在文件目录中运行以下命令。默认目标是 `192.168.4.1:8555`。

Windows PowerShell：

```powershell
py -3 .\daikin_stock_ota.py .\daikin-bry88ab.application.bin --sha256 649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e
```

macOS / Linux：

```sh
python3 ./daikin_stock_ota.py ./daikin-bry88ab.application.bin --sha256 649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e
```

发送器默认发送原厂协议版本标签 `SV.02.00.01.16`，用于通过当前原厂版本的准入检查；这不是刷入后的社区固件版本。镜像内容不受该标签改写。若未来换用另一份镜像，必须同时使用该镜像对应的 SHA-256，且重新确认机型和原厂布局适配。

正常过程会看到：

```text
Kit2 Version Up -> Okey
SV.02.00.01.16 -> ToDo
ACK .../1027296 (...%)
Final response: b'OK'
```

等待最终 `OK` 以及设备重启。发送器每块等待长度 ACK，并在 `End` 后留出独立校验阶段；请勿手工用 `curl` 上传、把应用当作 HTTP 正文发送，或把多个协议步骤粘在同一次 TCP 写入中。这里的原厂 OTA 不是网页上传接口。

## 6. 连接社区热点并验证

重启后，电脑连接新的开放热点 **`DAIKIN-XXXXXX`**，后缀为设备 MAC 的末六位。本次是 `DAIKIN-f76748`。旧热点可能短时间仍出现在系统缓存里，以新连接成功为准。

浏览器打开 **http://192.168.4.1**。检查页面中的设备型号、ID 和固件版本；本次实测返回 `BRY88AB151K`、`9c9c1ff76748`、`0.9.21-2cfd89-dirty`。然后按需要配置路由器 Wi-Fi、管理密码和 MQTT。

本次首次启动 PM2.5、温湿度、TVOC 有有效数据；CO2 当时仍处于预热，HCHO 没有检测到，原厂也存在 HCHO 无数据错误。不要把上传成功等同于全部传感器正常。

本次确认了原厂 bootloader 和分区表保留、社区应用从原厂第二槽 `0x190000` 启动。原厂联网配置不会自动成为社区配置；小 NVS 下的配置保存、断电持久化、第二次社区 OTA 尚未在本次流程中验证。不能据此把后续镜像上限放宽到社区默认分区配置的容量。

## 7. 常见问题与恢复

| 现象 | 检查与处理 |
| --- | --- |
| 找不到热点 | 确认原厂程序正常启动、型号与版本匹配，以及三次手势是否生效；OTA 任务本身不保证在所有配置状态下创建 AP。 |
| 能连热点，但 8555 超时或拒绝连接 | 先确认没有自动切网、设备网关确为 192.168.4.1；热点出现不等于 OTA 服务已启动，有条件时观察两条 OTA 日志。 |
| 握手返回 No / 版本未通过 | 停止，检查原厂版本和协议适用范围，不要随意换高版本标签绕过兼容性判断。 |
| 传输中断、ACK 异常或最终 NG | 保存终端输出，保持供电并观察设备状态；不要仅凭已传字节数判断刷入成功。没有重启到社区固件的证据时，不要继续后续社区升级。 |
| 返回 OK，但新热点未出现 | 等待重启并重新扫描，再检查串口日志；确认 GPIO0 没有因此前调试而继续接地。 |
| 无法启动 | 使用自己的完整 Flash 备份，通过 ESP32 串口下载模式恢复；GPIO0 与 EN 的操作属于串口恢复，不属于无线 OTA 手势。 |

实测成功范围是上述 BRY88AB151K 原厂版本到该固定社区镜像的首次迁移。其他机型、配置状态及后续升级需要分别验证。
