# 大金 BRY88AB151K：通过原厂 OTA 刷入社区固件

先选择电脑的操作系统，后面的文件检查和上传步骤会一起切换命令。Windows 使用 PowerShell，macOS / Linux 使用终端；浏览器未启用 JavaScript 时会显示全部系统的命令。

## 1. 原理与准备

原厂在进入升级模式后开放 TCP 8555 服务。电脑连接设备热点，通过专用发送器完成握手、版本检查、分块传输和校验。成功后，设备把启动分区切换到备用槽，再重启运行社区应用。

准备以下物品：

- 一台型号与原厂版本匹配的大金设备，使用稳定的正常电源供电。
- 能连接 2.4GHz Wi-Fi 的 Windows、macOS 或 Linux 电脑，以及 Python 3。发送器只使用 Python 标准库，不需要安装第三方 Python 包。
- 配套发送器、应用镜像及其 SHA-256。先在电脑仍能上网时下载。
- 对应设备的恢复条件。建议首次尝试前经串口保存自己的完整 4MB Flash 备份；不要下载别人的完整备份覆盖设备身份和私人配置。

电脑可以用有线网络上网、Wi-Fi 连接大金；只有一张无线网卡也可以，文件下载完成后切换到大金热点即可。刷机期间电脑不必能访问互联网。

**进入原厂 OTA 模式就会初始化并擦除备用应用槽，并非等开始上传才擦除。** 传输和切换期间不要断电。

## 3. 用按键进入原厂 OTA

设备正常上电、运行原厂程序后，找到**设备背面的 RESET 按钮孔**，用合适的细杆轻按孔内按钮，连续执行：

1. 按住约 **3 秒**，松开约 **0.5 秒**。
2. 再按住约 **3 秒**，松开约 **0.5 秒**。
3. 再按住约 **3 秒**，松开。

每次长按需要落在约 2～5 秒之间，每次松开到再次按下的间隔不要达到 2 秒。不要把三次合成一次长按，也不要每次按到 5 秒以上。本次这套手势已实测触发 `mode 0` OTA 任务。

**原厂某些配网状态下，长按会恢复配置并重启，而不是累计 OTA 手势。** 已知判断与原厂内部 `wififlag` 有关，不能把这套操作当作所有状态都不会清配置的手势。若设备重启或手势没有生效，先观察状态，不要反复延长按压时间。

有串口观察条件时，成功日志包含：

```text
Start OTA Task Suceess, mode 0
app_ota_server_create success
```

无线操作不要求连接串口；串口日志是排查手势失败的方法。

## 4. 电脑连接原厂热点

在电脑 Wi-Fi 列表中找到 `daikin!` 开头的设备热点，输入原厂此版本的默认热点密码 **`12345678`**。

本次实测热点名为 `daikin!f76748f9`。每台设备后缀可能不同，不要照抄示例名称。优先对照自己设备的 MAC；实测设备 STA MAC 为 `9c:9c:1f:f7:67:48`，对应热点 BSSID 为 `9c:9c:1f:f7:67:49`。

连接后，实测电脑通过 DHCP 获得 `192.168.4.2/24`，网关与设备地址为 **`192.168.4.1`**。系统提示“无互联网”属于正常现象，请保持连接。不要继续使用刷机前设备在路由器中的旧 IP；检查电脑是否自动切回其他 Wi-Fi。

Windows 推荐直接通过系统 Wi-Fi 菜单连接。若用 `netsh` 在远程 SSH 会话中连接，本次发现 current-user profile 会返回 `0x57`，改用该热点的 all-users profile 才成功；不要为此删除其他网络的配置。

## 5. 先探测可接受的版本标签

原厂只接受**高于当前版本**的标签，固定使用 `.16` 会被较新原厂版本拒绝。保持当前设备网络连接，先遍历一个明确范围，不指定固件文件：

<!-- os:windows -->

```powershell
py -3 .\daikin_stock_ota.py --probe-versions SV.02.00.01.16 SV.02.00.01.32
```

<!-- /os -->

<!-- os:mac linux -->

```sh
python3 ./daikin_stock_ota.py --probe-versions SV.02.00.01.16 SV.02.00.01.32
```

<!-- /os -->

每次间隔 **2 秒**；遇到 `ToDo`、异常响应、超时或其他通信异常立即停止。探测只发送握手和版本头，**固件数据为 0 字节**，不发送 `End` 和校验字节，不切换 Wi-Fi，也不会自动刷写。

例如，`.16`～`.20` 返回 `b'No' / EOF`，`.21` 返回 `b'ToDo' / complete`，关键输出为：

```text
观察结果：
  最高明确拒绝标签：SV.02.00.01.20
  首个接受标签：SV.02.00.01.21
固件数据发送量：0 字节；不会据此自动执行刷写。
```

通信异常需先排查。下面上传命令中的 `.21` 应替换为本机首个接受标签。

## 6. 上传应用镜像

确认当前连接的是自己的大金热点，在文件目录中运行以下命令。默认目标是 `192.168.4.1:8555`。

<!-- os:windows -->

Windows PowerShell：

```powershell
py -3 .\daikin_stock_ota.py .\daikin-bry88ab.application.bin --sha256 649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e --version SV.02.00.01.21
```

<!-- /os -->

<!-- os:mac linux -->

macOS / Linux：

```sh
python3 ./daikin_stock_ota.py ./daikin-bry88ab.application.bin --sha256 649a7b81b35e19510f9f7edb8488157418117849361bc62c6f4e13c61a5fb19e --version SV.02.00.01.21
```

<!-- /os -->

`--version` 只是原厂协议的准入标签，不是社区固件版本，也不会修改镜像。上传必须显式指定，脚本不会自动沿用探测结果。机型、原厂分区和镜像 SHA-256 仍需独立核对。

正常过程会看到：

```text
Kit2 Version Up -> Okey
SV.02.00.01.21 -> ToDo
ACK .../1027296 (...%)
Final response: b'OK'
```

等待最终 `OK` 以及设备重启。发送器每块等待长度 ACK，并在 `End` 后留出独立校验阶段；请勿手工用 `curl` 上传、把应用当作 HTTP 正文发送，或把多个协议步骤粘在同一次 TCP 写入中。这里的原厂 OTA 不是网页上传接口。

## 7. 连接社区热点并验证

重启后，电脑连接新的开放热点 **`DAIKIN-XXXXXX`**，后缀为设备 MAC 的末六位。本次是 `DAIKIN-f76748`。旧热点可能短时间仍出现在系统缓存里，以新连接成功为准。

浏览器打开 **http://192.168.4.1**。检查页面中的设备型号、ID 和固件版本；本次实测返回 `BRY88AB151K`、`9c9c1ff76748`、`0.9.21-2cfd89-dirty`。然后按需要配置路由器 Wi-Fi、管理密码和 MQTT。

本文附带的过渡镜像使用上述旧热点名称和地址。升级到 v0.9.25 后，恢复热点使用 `BRY88AX151K-AP-<MAC末六位大写>`，地址为 `http://192.168.0.1/`。已配置路由器 Wi-Fi 时，日常仍通过路由器分配的 IP 访问。

等待传感器预热后检查读数；CO₂ 预热可能较慢，未安装甲醛传感器的设备没有 HCHO 读数。

此流程保留原厂 bootloader 和分区表，社区应用从第二槽 `0x190000` 启动。首次启动需重新配网；后续镜像仍须适配原厂 1.5 MiB 应用槽。

## 8. 常见问题与恢复

| 现象 | 检查与处理 |
| --- | --- |
| 找不到热点 | 确认原厂程序正常启动、型号与版本匹配，以及三次手势是否生效；OTA 任务本身不保证在所有配置状态下创建 AP。 |
| 能连热点，但 8555 超时或拒绝连接 | 先确认没有自动切网、设备网关确为 192.168.4.1；有条件时检查两条 OTA 服务启动日志。 |
| 握手返回 No / 版本未通过 | 按第 5 节只握手探测可接受标签；同时核对镜像型号和校验值。 |
| 传输中断、ACK 异常或最终 NG | 保存终端输出，保持供电并观察设备状态；等待重启并确认社区版本后，再进行后续升级。 |
| 返回 OK，但新热点未出现 | 等待重启并重新扫描，再检查设备启动日志。 |
| 无法启动 | 停止反复尝试无线升级，使用自己的完整 Flash 备份寻求串口恢复。 |
