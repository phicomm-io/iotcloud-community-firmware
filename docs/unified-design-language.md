# 统一设计语言：实现记录

本文记录三款设备共用的设计与协议约定。接口细节见 [WebUI 约定](webui-contract.md) 与 [TMCP 协议](mqtt-account.md)。

## 已接入的行为

- 三款 WebUI 共用颜色、排版、间距、表单、导航和诊断组件样式。浅色、深色及跟随系统的选择只保存到浏览器本地。
- 指示灯共用状态优先级和单调时钟时序：未配网 > Wi-Fi 断线 > MQTT 已配置但未就绪 > 正常。慢闪 1000/1000ms，快闪 150/150ms；未配网为三次 800ms、三次 200ms，相邻脉冲间隔 200ms，末次结束后停顿 2000ms。
- M1 的 Wi-Fi、错误图标独立输出；关闭输出时切换 GPIO 为低电平。A1 在业务灯效渲染后覆盖故障灯，并服从夜间亮度上限。正常状态归还 TC1/A1 业务灯控制权。
- 默认开放热点分别为 `TC1_A1-AP-ABC123`、`A1-AP-ABC123`、`M1-AP-ABC123`，后六位 MAC 大写。
- 新 Wi-Fi 凭据只存 RAM。要求匹配目标 SSID、收到本次 DHCP 通知并取得非零 IP，30 秒内验证成功才保存。超时或存储失败恢复旧配置，没有旧配置时保留配网热点。SDK 的 Wi-Fi 参数自动保存通知已禁用。
- 本次启动未连接成功时，五分钟后开启临时热点且继续 Station 重连；成功连接后再断线不自动开热点。
- TC1 自定义按键事件默认留空，短按和 1–4 秒普通长按均不执行动作；已保存的用户配置在升级时保留。按住时每满一秒亮灯 160ms，期间熄灭，松手后恢复业务或网络指示灯状态。闪灯只反馈时间，不提前执行恢复。
- TC1/A1 功能键在松手时执行恢复：5–10 秒清除 Wi-Fi 和网页密码，10 秒以上清除全部配置。固定恢复手势绕过童锁；普通物理动作受童锁约束。TC1 完整重置保留六路默认开启。
- M1 使用原面板 `0x18` 长按事件，发送固定 `0x16` ACK，单次启动去重后清除 Wi-Fi 和网页密码；不宣称面板支持精确的 5/10 秒分段。M1/A1 WebUI 提供完整重置。

## M1/A1 MQTT 模式

M1、A1 固定使用 TMCP（Tom MQTT Cloud Protocol）主题，不提供 legacy 模式选择。旧配置中的模式标记在启动时归一化为 TMCP，保留 Broker 地址、端口、用户名和密码；保留原字段位置以维持存储布局。运行时不会依据旧标记切回旧主题。TC1 保留 legacy / TMCP 两种模式，首次配置 MQTT 时默认 TMCP。

设备主题为 `phicomm/v2/<scope>/<model>/<mac>/...`，非空用户名对应 `u_<UTF-8 字节的小写十六进制>`；空用户名使用 `local`，仍使用同一套 v2 协议。HA 发现配置发布到 `homeassistant/<component>/<scope>/<model>_<mac>_<entity>/config`。TMCP 账户隔离仍需 Broker ACL 配合，固件主题前缀本身不构成权限隔离。

## M1 与 A1 联动

A1 添加 M1 后生成 `a1_mac:m1_mac`（两侧均为 12 位小写十六进制）的组合 MAC。每个标识只授权一个 A1 查询一个 M1，添加其他 M1 不改变已有标识。M1 粘贴许可列表，最多八个并去重；不再填写 IP、令牌、恢复间隔或联动规则。

A1 发起会话初始化、探测和查询，优先 LAN、失败回退 MQTT。M1 只被动响应许可 A1 的 `bind`、`probe`、`read`，会话令牌仅存 RAM；回复沿固定目标主题或 UDP 实际来源返回，不接受自定义回复主题。M1 重启后 A1 周期初始化会话，不需要用户重填令牌。

M1 拒绝联动通道的配置读写、解绑和传感器推送；不主动轮询 A1，不主动发布联动镜像。传感器自身 MQTT 与 Home Assistant 功能仍保留。规则、聚合、风机、灯环和组控制集中在 A1。M1 配置版本 4 从旧版本保留本地设置，并将原对端信息迁移为去重查询权限，清除旧 IP、令牌、组和联动规则。

双方需一起升级。TMCP 使用统一 v2 主题与命令结构；M1/A1 不保留早期专用协议兼容层，TC1 单独保留 Legacy。

## 公共服务

- `/api/v1/command` 与 TMCP command 共用动作、参数校验、结果码及请求去重；能力列表按产品提供。
- 一次性与每周任务，稳定 ID、持久化后执行、错过不补触发；TC1 128 项、A1/M1 8 项。任务与按键列表最多每页 8 条，前端分批加载。
- TC1/A1 支持自定义按键事件；5/10 秒恢复手势独立于自定义映射。公共日志使用 64 条 RAM 环与固定事件词表，不记录凭据。
- A1 对已绑定且 15 秒内有效的 M1 数据计算实时算术平均；无有效数据时读数为 null。HTTP、首页与 MQTT average 使用相同结构。
- 三端共用首页/二级设置导航、词表、表单反馈、认证、OTA 与诊断组件。

## 验证边界

主机测试覆盖灯语边界、时钟回绕、Wi-Fi 候选隔离、过期 IP 拒绝、配置合并、超时/存储失败回滚，以及 M1 许可、会话和禁止写入。TC1 另编译实际试连函数，模拟错误 SSID、过期 DHCP、Flash 保存失败和线程创建失败。浏览器模拟覆盖绑定表单、主题保存、未保存字段及 OTA 明确选择。已有签名 OTA 测试继续保留。

已通过 `tests/run.sh`、`tests/run_tc1.sh`、`tests/ota/run.sh`、两套 WebUI 浏览器模拟和三款实际固件构建。MQTT 主机桩明确拒绝下载固件；隔离 Broker 测试覆盖实际 SDK MQTT worker，但不代表真实设备或 Home Assistant 已验收。

实际构建不等于刷机或硬件验收。A1 槽位 27 来自原 Wi-Fi 指示槽，仍需确认其是否为用户指定的物理中心灯珠；M1 长按事件、TC1/A1 松手边界、AP/Station 共存和真实断电回滚也需设备验证。固件构建、设备 OTA 校验、重启后接口、Home Assistant 加载与物理输出分别验收；不能用其中一项替代其他项目。
