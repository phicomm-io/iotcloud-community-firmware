## 开发变更

1. 将已验证的资源优化和 A1/M1 联动四台限制迁移到最新 main：订阅按四条分配、队列保存紧凑目标、状态保存必要字段、小临时快照、TC1 日志启动初始化。保留原 Flash 配置偏移和八槽存储布局，旧配置只启用前四台。
2. MQTT 业务回包入队时立即序列化并释放整个 JSON 对象树，只保留独立文本缓冲。队列仍为四槽，发送仍由 MQTT owner 执行，保留原目标账号、Legacy TC1、嵌套回调、发送失败及重连清理行为。

第二项减少积压时的对象树，不减少常驻线程栈。没有引入新的累计字节配额，文本缓冲仍按回包大小动态分配。序列化提前到回调阶段，会与接收缓冲重叠，单请求瞬时峰值及实机总体峰值仍需要验证；不能把队列保留量的下降直接当作最大堆峰值下降。

以本轮实机状态响应为样本，使用固定 SDK 重新解析、按 ARM GCC 实际验证的结构体尺寸计算对象、散列表、数组、键和值，并用同一 SDK 序列化器测量文本容量：

| 样本 | 单份对象树载荷估算 | 单份文本缓冲含 printbuf | 四份队列保留量估算下降 |
| --- | ---: | ---: | ---: |
| A1 status | 7399 B | 3856 B | 14172 B |
| M1 status | 7728 B | 3856 B | 15488 B |

这是已有设备状态样本的结构尺寸估算，未包含 MCU 分配器头、对齐、碎片、构造/扩容瞬态和 MQTT request_id；不是分配器实测或新候选的最坏情况承诺。新 main 状态字段变化也会改变回包大小。
