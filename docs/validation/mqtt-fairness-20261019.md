# MQTT 动态回执队列与发送顺序优化（2026-10-19）

本轮仅验收 A1（b0f893303134 / 10.117.152.111）、TC1（d0bae463e12c / 10.117.152.102）。M1 已由用户交给其他线程，本线程不探测、不部署、不施压。前轮结果见 [动态内存保护](dynamic-memory-20261019.md)。

## 改动与边界

固件提交 `f91e40f954e7c8a65ef4f7fbe921d9dbb8b916c6`，运行版本 `0.9.13-f91e40`。

- 普通 MQTT 回执元数据改为链表，按实时堆余量分配，不再因固定四项数组满而直接拒绝。目标信息在执行命令前复制，发送时生成主题；排队持有独立 wire，不保留完整 JSON 图。
- 每项元数据在 ARM 上为 228 B，另有 SDK 分配器开销与独立 wire；累计占用仍由逐次分配保护限制。动态队列并不免费，也不保证任意速率无限排队。
- 保留四个静态紧急条目，只存目标及已校验的 request_id；当元数据申请被保护拒绝时，既不解析 JSON、也不执行命令或申请 wire，发送时在栈上生成 busy。四个紧急条目同时耗尽仍可能没有回包，明确累计 mqtt_overflow，不声称任意洪峰都逐条受控。
- 单次 flush 只处理进入时的待发数量，期间回调新到请求留给下一次，避免持续到达使本次循环无法退出。发送前释放节点或紧急位置；发送失败清理当前 wire，断线退出立即回收其余节点和 wire。只在 MQTT owner 发送，保持禁止回调嵌套 QoS1 发布的约束。
- A1、TC1 owner 在低优先级工作之前和 MQTTYield 之后发送回执；快照发送前若仍有新回执则推迟本次遥测。保留采样、控制、网络保活等既有行为。
- 两款 /api/v1/memory 增加 mqtt_pending、mqtt_peak、mqtt_overflow、mqtt_max_delay_ms；这是当前排队量、开机以来峰值、紧急队列溢出次数和入队至发送开始的最长时间，后者包括构建响应时间，不包括 socket 发送/PUBACK 等待。诊断使用 768 B 栈缓冲，不申请堆。

16 KiB 核心余量仍为软目标，不是隔离内存池；闭源 SDK 的分配、碎片和并发消耗仍不可全面观测。TCP 安全上限 2 未改，未完成按内存动态接收 TCP 连接；A1/M1 四台联动产品约束未改。本轮两 HTTP 工作线程不能证明更高 TCP 并发也逐条受控。

## 实机验证

一个执行器逐台，只读 status.get/config.get；唯一 request_id，拒绝 retained 回包。每组 45 秒、2 个 HTTP 工作线程、每秒至多一批 4 条 MQTT，批内间隔 50 ms；HTTP 每线程间隔 150 ms。大正文为填充至 8192 B 的合法 JSON；worker 零每秒用一次 memory GET 替换压力请求，不增加探针连接。HTTP 超时 20 秒，MQTT 回包窗口 4 秒，失败如实保留。每阶段撤压 10 秒后完整核对状态。

四组均完成，无资源停止事件，配置、控制、健康和升级后 uptime 检查通过，MQTT 错误增量为 0。以下计数格式为成功 / busy / 失败，失败没有重试后改记成功。

排队峰值和最长等待为开机累计值，不是每阶段独立复位。四组共 MQTT 720 条，441 成功、279 busy、0 超时；mqtt_overflow=0、JSON 原生分配失败=0。HTTP 共 687 条，601 成功、84 busy、2 次 ConnectionResetError，均发生在 A1，不能归入受控 busy。因此本轮 TC1 有界混合负载逐条受控通过，A1 和整体逐条受控尚未通过；无观测到重启不等于串口确认了复位原因或全局零 OOM。

对比前版 7ff2ab 同类两 HTTP 工作线程测试：TC1 大正文 MQTT 从 77 成功 / 41 busy / 14 超时（132 条）改善为 103 / 77 / 0（180 条）；HTTP 从 116 / 8 / 0 改善为 137 / 7 / 0。超时会拉低实际发出量，两次不能当作相同发送总量计算成功率。TC1 普通正文 HTTP 成功量由 209 降为 187，未改善；A1 普通正文 HTTP 成功量由 166 增为 183，但新增 1 次重置；A1 大正文 HTTP 成功量由 105 降为 94，重置仍为 1 次。没有将所有指标表述为改善。

A1 两次重置前后 accept 队列拒绝、busy 发送失败、溢出关闭计数均未增加；缺少逐请求 socket/SDK 级证据，根因未定，不据此宣称是 OOM、重启或已解决 TCP 接入问题。A1 保护点最小余量 15012 B 也表明 16 KiB 只是软余量，不能保证所有时刻高于此值。
