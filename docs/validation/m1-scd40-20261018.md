# M1 SCD40 接线测试（2026-10-18）

目标：M1 `b0f8932864b6`，地址 `10.117.152.110`。

## 实现

- `M1/scd40.c` 使用 I2C1（SDK SDA GPIO8 / SCL GPIO7），7 位地址 `0x62`，标准速率。
- UART 工作循环调用非阻塞等待状态机，先停止测量、等待至少 500 ms、读取带 CRC 的序列号，再启动 5 秒周期测量；写命令与读数据分开 STOP。
- 校验每个 16 位字的 CRC-8；无效或超过 20 秒的数据返回 null，不冒充零浓度。
- `/api/v1/status` 的 `data.scd40` 提供采样、通信/CRC 错误、初始化及失败阶段诊断。原传感器字段保留。
- 此次仅接入状态接口，未增加网页卡片、MQTT Discovery 或原装屏幕显示。

## 验证

- M1 原生构建、镜像检查、浮点支持检查和已有栈预算检查通过。
- `tests/test_m1_scd40.c`：Sensirion BE EF -> 92 已知 CRC、字节序和全部 72 种单比特损坏检验通过；ASan/UBSan 通过。
- 本地 P-256 签名及可信公钥复验通过。私钥未写入仓库或证据。
- 源码基线 `e9cda6e855c468f2bddae2e5c542e0bfa26f6925` 加本地测试改动；运行版本 `0.9.7-e9cda6-dirty`，不是正式发布。
- 第一版签名 OTA 返回 HTTP 202。10 次观测覆盖约 48 秒，uptime 从 31784 增至 79888 ms；原传感器有效，UART errors=0，MQTT 已连接，看门狗 healthy。
- **SCD40 读取 FAIL**：serial 为空、samples=0，错误从 6 增至 16，`last_error=-6722`（SDK kTimeoutErr）。CRC 错误为零不代表曾成功通信。
- 65 秒采样脚本在第二次诊断 OTA 期间 HTTP 超时退出；这不是完整的 65 秒验收。
- 第二版补充 `bus_initialized` / `last_command` / `error_phase`，签名 OTA 返回 HTTP 202；升级后暂未读回新诊断，不能声称已确认具体失败阶段。
- 第二版原生镜像 SHA256：`664db6db031b948ed6f2260a972ea489256e6ee287039a6af8606c44dca6afde`。

## 首次取得真实 CO2 数据

再次调整后，本次启动成功读取序列号 `f701a3073b32` 以及四组 CRC 有效的测量，CO2 依次为 684、672、660、646 ppm。第四组温度 22.449 C、湿度 55.010 %RH。启动早期原 UART 采样尚未到达，最初 20 秒脚本因此未通过原传感器有效性断言；随后原传感器、MQTT 和看门狗均恢复正常。

后续稳定性观测中 SCD40 samples 持续停在 4，命令停留为数据就绪查询 `0xE4B8`，通信/CRC 错误仍为 0；数据超过 20 秒后 valid=false、浓度返回 null。这证明曾成功读取真实传感器数据，但不证明持续测量正常；当前连续采样验收未通过。未对供电、传感器复位或总线/驱动原因作确定归因。配置接口与升级前快照一致。
