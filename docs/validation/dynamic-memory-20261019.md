# 实时分配保护与泄漏审计（2026-10-19）

前一轮实机压力结果见 [busy 验收](busy-acceptance-20261019.md)。本轮目标是减少统一估算造成的保守拒绝，并增加泄漏证据。不能承诺闭源 SDK 全系统、无限运行时间绝对零泄漏或零 OOM。

## 实现

- HTTP/MQTT 业务准入改为 `512 + 输入字节数` 的未分配正文/调度预留，不再统一预留 `12288 + 2 × 输入字节数`，也不按在途请求数量拒绝。空正文门槛从 28672 B 降为 16896 B；8192 B 正文门槛从 45056 B 降为 25088 B。预留仍保守地与实际已分配内存叠加，避免承诺尚未分配的空间。
- 对 pinned JSON 库的 malloc/calloc/realloc/strdup、v1 HTTP 正文及控制回执副本，逐次检查 SDK 实际空闲堆：保留 16384 B，再扣除本次请求和 32 B 分配器元数据/对齐余量。realloc 按完整新块检查，覆盖先申请后复制的瞬时峰值；失败保留旧块。乘法溢出提前拒绝，free 始终允许。保护和计数使用独立 mutex；无每块额外头部或动态统计表。
- 降低门槛后若中途空间不足，释放部分 JSON，并让现有传输固定 busy 路径接管；不会返回外观成功的残缺 JSON。全局单调失败计数用于跨层检测，因此并行其他请求的失败也可能保守地使当前响应返回 busy。控制回执仍保持至多执行一次，已执行但无法保存响应时，同 ID 重放返回 busy。
- `/api/v1/memory` 增加 `json_live_blocks`、`json_peak_blocks`、`json_alloc_failures`、`json_guard_denied`。前两项是当前存活/历史峰值块数，后两项分别是底层实际分配失败与提前保护拒绝；拒绝不调用底层分配器。统计覆盖上述可见路径，不是整个 SDK。有限回执缓存、待发送 MQTT wire 及并发核心工作可产生合法存活块，不能要求任意时刻全部为零。
- JSON 库导出的 strndup 也服务 URL 模块；其调用方用原生 free，故保留原生 ABI 和统计边界，避免把外部释放误判为 JSON 泄漏。内部长格式字符串使用私有兼容分配函数，保证统计配对。
- 初始化 mutex 失败后重试会复用已成功创建的 mutex，避免重复初始化泄漏。TC1 构建补齐同一组 JSON 安全补丁，避免仅依赖既有 SDK 缓存中已经打过补丁。

## 核心业务与连接边界

16 KiB 是留给硬件控制、采样、MQTT 网络保活和其他 SDK 瞬时开销的软余量；它不是物理隔离的核心内存池。控制、采样的已有静态缓冲/线程不受业务请求计数准入限制。SDK 的其他原生分配可以与保护检查并发，碎片也可能导致分配失败，因此仍必须处理 NULL；上述计数不能代表 SDK 全局失败次数或最大连续块。

A1/M1 的 FIFO 为 1，三款 TCP 安全上限仍为 2；这是尚未完成的连接层限制，不能把本次业务分配改造说成已实现按余量动态连接数。MOC 在业务检查前就分配 TCP 接收内存，无可用接收缓冲配额接口。此前重复设置 TCP_MAX_CONN_NUM 的版本出现重启；尚未证明修改活跃 listener 是安全的。本轮不直接放开这一边界，之前“所有请求均正常或受控 busy”的 FAIL 也不会因此改为 PASS。A1/M1 四台联动数量为先前明确要求的产品约束，本轮不改变。

## 验证范围

主机验证包括真实 pinned JSON 库的 10000 轮串行及 4000 轮并发解析/序列化/释放，逐个底层分配与保护拒绝点注入，独立原生分配账本检查归零；导出 strndup 的 URL 释放兼容；真实业务调度器的 10000 轮回收、内存中途耗尽、残缺成功响应抑制、控制回执和 64 个请求依赖字节预算准入。完整 ASan/UBSan 检查与 ARM 构建结果以本轮最终日志为准。

实机部署及多轮压力/恢复趋势结果将在验证后单独记录；不能把此前版本的无重启结果当成本次新分配器实现的证明。有限周期趋势只能说明已测范围未观察到泄漏，不能证明 SDK 任意路径、无限运行时间均无泄漏。
