# S30-V1B stock OTA guide correction — 2026-11-04

Two additional ORVIBO S30-V1B / BL2028N / BK7231N units were installed from stock S30M/v0.0.7 to the published `v1.0.0-rc.5` RBL. Both reported `1.0.0-rc.5-8634a1`, their individual factory MAC, storage ready, safe mode off and OTA idle after installation. Each retained Wi-Fi and MQTT configuration across a software reboot; both broker availability topics reported online. Live HLW8032 voltage/current/power fields were valid. This run did not perform a load or calibration-accuracy test.

The installed release file was 496592 bytes, SHA-256 `b324f366b71382fa7ce2b0e5516fced7e9733f956d3b320b9c1fbb5ea69e9558`. Its GitHub asset digest and `SHA256SUMS-S30` matched; local RBL header/payload CRC checks passed. Release build/validation metadata identified clean source `8634a1c6f3cff1a71e57321500ee8afd72e161ff` and the stock layout preserving the original bootloader and factory partition.

The live sequence used stock AP CoAP provisioning, local HTTPS bootstrap/boot/dmReport, a dedicated TLS MQTT broker, and a port-80 HTTP download with no explicit port in the URL. It required no router NAT/DNS changes or serial connection. The temporary installation services and credentials were removed afterwards.

The previous guide downloaded the installer from the RC5 tag, whose script emitted an explicit `:8080` firmware URL. That URL is incompatible with the inspected stock hostname parser. A previous live attempt produced a File event without an HTTP request, leaving the stock OTA busy flag set for 600000 ms. The corrected tool listens on port 80, emits `http://host/s30.rbl`, and rejects nonstandard HTTP ports. Both language guides now download the maintained installer from main, explain binding port 80, and distinguish the target LAN IP from the stock AP provisioning address.

The tool also sends HTTPS headers and JSON together, matching the transport used in the successful installations, and uses a separate MQTT identity/topic per factory MAC. The revised standalone tool was checked with real local TLS sockets across bootstrap/boot/dmReport, real HTTP delivery, and rejection of port 8080. The two physical installations used the equivalent local gateway flow before the standalone-tool edit; they are not a hardware run of the revised CLI itself.
