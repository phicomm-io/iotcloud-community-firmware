# A1 内存与空间优化

功能基线提交：`4c504f10`。本优化独立于功能提交。

`SERVICE_MEMORY_RESERVE=16384` 是堆分配软门槛，不是预分配内存，也不是 HTTP/MQTT 线程栈大小。降低到 12288 可多放行 4096 字节的动态分配，不会减少固件 Flash 占用。HTTP 并发槽满、JSON 独占 lease、OTA/重启/配网忙状态也会返回 busy；不能仅凭 busy 归因。

已优化：共用独立的 linkage 编解码函数，新风策略不再为少量字段临时分配完整的 1408 字节 feature_config_t。保持相同参数、校验和事务语义。完整新风构建应用载荷由 262084 降至 261924 字节，当前余量 220 字节；版本元数据和后续修改仍会影响最终尺寸。

实际 ARM/newlib 配合合成分配账本测试 `tests/test_a1_fresh_air_budget.py` 比较 16 KiB 与 12 KiB 门槛：普通新风状态 GET 在 16 KiB 门槛下，模拟空闲堆 20000 字节会 busy，21000 字节成功，动态峰值 3688 字节；POST 峰值 4224 字节。12 KiB 可以降低所需空闲堆，不能证明真实 SDK 并发分配和碎片化的安全余量。因此生产默认暂保持 16 KiB。

下一步优先采集设备 `/api/v1/memory`（该接口自身也需要约 2.3 KiB 分配）中的 free_memory、minimum_sampled_free、memory_denied、json_guard_denied、HTTP 拒绝/关闭计数和 MQTT 队列数据。在 Wi-Fi 重连、HA 发现、双 MQTT 和浏览器刷新同时发生的实际负载中比较 16/12 KiB。没有实机数据时不宣称降低门槛已解决 busy。

其他方向：减少自动化/发现路径存活的全量配置副本、减少重复状态发布，按实际调用链栈水位评估线程栈。Flash 方面优先共享编解码路径和压缩前端；单纯将 zopfli 迭代从 15 提高到 100 此次仅节省 24 字节，不足以解决容量紧张。
