# M1 原厂 MCU 屏幕校时补发

用户反馈：0.9.27 与 1.0.0-rc.5 都可能在 NTP 成功、温湿度正常时仍显示 2000-01-01；修改时区后恢复。该现象支持首次时间下发未生效的方向，但尚无故障机串口抓包确定原因。

## 协议参考与边界

对照配套 MCU 仓库 `phicomm-io/phicomm_m1_mcu_atsamd20` 的
`01af1ebccdaf48b73d02eaaf7023f68d5a0d280f`：

- `docs/protocol.md` 的 `03` 设置时间帧：大端完整年份、月日时分秒，与本仓库 `m1_clock_frame()` 一致。
- `docs/stock-analysis.md` 的原厂 `i2c_rtc`（0x5370）与 `sem_task` 分析：RTC、显示拥有独立任务/调度，不能把联网模块获取 NTP 当作显示更新完成。

本次使用已有原厂 MCU 逆向资料参考协议和任务边界，没有重建原厂 Wi-Fi 固件的 NTP 重发策略。60 秒补发与 1 秒发送失败重试是本次新增的恢复策略，不声称来自原厂。

## 行为

保留现有 NTP 小时周期及失败 60 秒重试。UART 线程另行每 60 秒从软件 UTC 时钟和当前时区构造 `03` 帧，发送失败每秒重试，使用有符号差值比较单调时钟 deadline。NTP 未成功前不发送默认日期。NTP 入队事件及 MCU `17` 帧触发立即重发；队列中的旧时间不会在长时间 MCU 升级后原样重放。MCU 升级、Wi-Fi OTA、待重启期间暂停。

该路径不需要 DNS、Wi-Fi 或队列空间，首次发送被 MCU 忽略后可在下一分钟恢复。`ntp_screen_queued` 保持原本入队语义；目前仍未实现 MCU 时间读回确认，UART 成功不代表屏幕实际更新。

## 验证

`python3 tests/test_m1_clock.py` 保留原 NTP 用例；
`python3 tests/test_m1_screen_clock.py` 直接编译生产补发函数，覆盖未校时启动、周期补发、当前时间/时区、发送失败重试、升级/重启暂停、时钟读取失败、毫秒回绕。

实机待验证：原厂 MCU 冷启动联网，保持时区不变；故意丢失首次校时后观察一分钟内恢复；NTP 成功后断网并重启 MCU，确认补发；升级期间确认没有校时帧干扰。本次主机测试及构建不能代替这些设备验收。
