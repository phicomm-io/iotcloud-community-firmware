## A1：Wi-Fi 图标键，约 1 秒启动接收

- 原厂 `0x0808aa26` 每轮等待 100 ms，再通过 `0x0808a61c` 读取三个触摸字节。输入 `FF 00 非零` 对应第三字节持续有效。
- `0x0808acf0` 要求计数 `r5 > 9`、本次按压锁存 `r4 == 0`、配网任务标记为 0，随后到 `0x0808abfa` 排队配网动作并锁存。本分支不检查是否保存过 Wi-Fi。
- 接收启动点 `0x0808fcb8` 传入 `0x3c`，即 60 秒。
- 与本仓库 [A1/hardware.c](../../A1/hardware.c) 和 [A1/buttons.h](../../A1/buttons.h) 的现有定义交叉核对：`raw[1]` 为电源，`raw[2]` 为 Wi-Fi。这是将原先“特定触摸输入”落实到 Wi-Fi 图标键的依据。

教程采用“单独按住 Wi-Fi 图标键 1–2 秒后松开”。这是按原厂分支及现有面板定义给出的操作说明；没有新增 A1 实际无线配网成功的声明。

## M1：短按、3 秒配网、9 秒恢复默认分开

外壳按键接传感器主控，由 UART 通知联网模块。联网模块的 GPIO 按键代码不是外壳操作入口；本轮按用户提供的板级连接事实纠正原文，并核对两端固件调用链。

原厂主控 `0x50ac` 配置低有效 PA10 / EXTINT10；`0x5104` 建立 10 tick 自动重载计时器，`0x4f4c` 累加计数，`0x4fa8` 处理释放。既有时钟调查为 8 MHz，SysTick reload 为 7999（镜像 `0x9274`），即每 tick 1 ms，按键计数间隔约 10 ms。

| 输入阶段 | 主控路径 | 联网模块处理 / 教程含义 |
| --- | --- | --- |
| 松开时计数 6–299，约 60 ms 至不足 3 秒 | `0x4fa8` 调用显示切换并排队 `0x0f` | 短按是屏幕操作 |
| 持续按住到计数 301，约 3.01 秒 | `0x4f4c` 唤醒 `0x5160` 按键任务，调用 `0x8268` 排队 `0x04`；发送任务 `0x85ee` 生成 20 字节 `23 04 … 21` | `0x08088b7c` 的 `0x04` 分支调用 `0x0808f5dc` → `0x0808e27c`，调度配置任务；这是正常配网入口，触发不必等松开 |
| 松开时计数至少 900，约 9 秒 | `0x4fa8` 排队 `0x18`；发送任务 `0x8b26` 生成 `23 18 … 21` | `0x08088d44` → `0x080887cc`（发 `0x16`）→ `0x0808f6e8` 恢复配置并安排重启；这是恢复默认入口 |
| 持续按住到计数 1000，约 10 秒 | `0x4f4c` 另排队 `0x10` 并置显示状态标记 | 不是将 3 秒、9 秒两个操作统一写成“长按 10 秒”的依据 |

3 秒分支的配置任务为 `0x0808e1fc`：取系统上下文、调用 `0x0808ddd0`，再以 mode 1 调用 `0x0809268c`（`mico_easylink`），创建入口为 `0x08091f2c` 的线程。线程在 `0x08091fd4` 格式化 `EasyLink_%c%c%c%c%c%c`，在 `0x08092006` 起以 120 秒参数启动 EasyLink + SoftAP。不能看到 `Poweronhold` 日志就把这个分支只解释成屏幕控制；必须追完它对配置任务的调用。

恢复默认分支先由 `0x0808e948` 清系统联网配置和 configured 标记，`0x0808f6e8` 另恢复应用设置，保存后重启。启动 `0x0808e372` 直接检查 configured 字节，未配置时也调用 `0x0808e27c`。此结论来自实际条件与调用，不是仅从日志文字推断。

因此正文写“按住 3–4 秒后松开进入配网”；9 秒后松开另列为恢复默认，并写明清配置的后果。社区联网固件对 `0x18` 的行为单独核对 [M1/uart.c](../../M1/uart.c) 与 [M1/main.c](../../M1/main.c)：调用 `m1_reset(false)`，清 Wi-Fi 与网页密码，保留其他用户配置。不能将原厂和社区对同一事件的处理混写。

## M1：主控确有联网模块硬件复位逻辑

原厂 UART `0x16` 非取消路径 `0x8aae`：

1. 若完整接收标记为 1，调用 `0x84a0` 提交升级元数据；没有完整数据也继续后续复位流程。
2. 等待 4000 tick，调用 `0xb5a4` 写 PORT OUTCLR `0x41004414 = 0x01000000`，使 PA24 低。
3. 等待 1000 tick，写 `SCB AIRCR = 0x05fa0004`，复位 SAMD20。
4. 主控启动包装函数 `0xb578` 写 PORT OUTSET `0x41004418 = 0x01000000`，使 PA24 高。根据既有板级调查，PA24 控制联网模块 CHIP_EN。

取消标记为 1 时生成 `0x1a` 应答，跳过上述等待、PA24 拉低及系统复位。硬件重启不等于清除联网配置；恢复配置是联网模块收到 `0x18` 后的另一段代码。

## 本地核验与仍需保留的边界

公开教程将验证说明简写为“M1 已实机验证配网可用；A1 经原厂固件逆向分析，理论上也可用”。原有实测记录包括：M1 热点提交返回 HTTP 200；另通过路由器的 2.4 GHz 信道 1 发送 EasyLink V2，核对关联、DHCP 和原厂 HTTP 身份。普通电脑驱动的空口发包兼容性未因此得到确认。A1 已有电脑端测试与原厂解码指令仿真，没有 A1 实际无线配网成功记录。

本轮本地证据目录：`build/stock-provision-review-20261028/`。

- `verify_entries.py` 先核对三份镜像 SHA-256，再执行原始 Thumb 指令；RTOS、GPIO、NVM 和无线底层调用使用桩，不访问设备。
- `evidence.json` 记录 11 个 M1 松开边界、4 个按住计时边界、4 个 A1 触发条件和 4 个 PA24 路径；另执行 M1 联网模块 `0x04` 分支及其配置任务，确认创建 EasyLink 线程。
- `m1-reset-disassembly.txt` 留存联网模块恢复设置、启动判断、3 秒配网调用链及热点启动点的反汇编片段。

复核命令（依赖本机已留存的原机备份和分析环境）：

```sh
../phicomm_m1_mcu_atsamd20/build/analysis-venv/bin/python \
  build/stock-provision-review-20261028/verify_entries.py
```

本轮没有补做实体按键、A1 无线收包、普通电脑网卡兼容性或任何刷写验收。已经有固件依据的按键、UART 和复位结论已定下来；A1 首次迁移镜像、公共 DNS 服务 / 旧 TLS 实测、掉电恢复等未获新证据的限制继续保留。TC1 和 DAIKIN 的既有教程也已检查，不能把 A1 / M1 的时长套用过去。
