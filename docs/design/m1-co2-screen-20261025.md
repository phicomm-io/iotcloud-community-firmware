# M1 CO₂ 实体屏幕与主控网络升级

配套主控使用 `0x70` 协议版本 2，能力位图 `0x3fff`。联网模块先通过 `0x11` 收到实际主控版本，再查询扩展能力；必须同时支持 0x0a–0x0d 且 SCD40 已读取到序列号，网页“设置 → 设备”才显示 CO₂ 屏幕选项。旧主控、未识别模块均隐藏；模块已识别但读数过期时仍可配置，实体屏幕自动恢复原污染物。

`co2_display.get/set` 使用 mode（0 不替换/1 完全替换/2 交替）、slot（0 甲醛/1 PM）、interval_seconds（1–3600）、low/high（0–65535 且有序）、revision 六项。set 必须完整给出六项，revision 实现比较后写入。默认不替换、5 秒、1000/1500 ppm。阈值影响 CO₂ 所在位置灯色与高档蜂鸣器策略。

配置结构版本从 6 升至 7；迁移保留原阈值记录和既有网络、绑定、自动化字段。旧版本固件不认识 v7，回退前应单独考虑配置迁移。主控配置保存在 RAM，联网模块重复同步；读数以采样年龄生成不超过 20 秒的 TTL，过期立即回原始显示。正常传感器字段及 A1 联动数据不被替换。

显示规则：小于 1000 为整数；1000–9999 显示 `1.00`–`9.99`，10000 以上显示 `10.0`–`65.5`，按 k ppm 理解。选中位置关闭污染物名称和原单位。屏幕没有新增 CO₂/k 文字，数码管段实际效果需实物观察。

`POST /api/v1/mcu/exchange` 接收 6–262 字节的二进制帧，允许扩展 0x70 和升级 0x12/13/16。复用 Web 密码认证，单 UART 所有者串行发送并匹配应答；升级期间屏蔽普通 UART 控制，互斥 Wi-Fi OTA 和配置修改。0x16 提交返回的是发送凭据，启动成功必须另查主控版本。主控仓库的 `tools/m1_network.py` 实现镜像校验、逐块 ACK/重试、提交与重启版本核对。

最初实机验证使用旧开发工作区 `0.9.11-79cd29-dirty`。随后功能迁入 `main` 的 `06abd351`，保留 main 的共享 HTTP、MQTT、统一状态编码、传感器会话授权和 BMP388/BMP390 支持；新 main 构建与此前实机验证分别记录，不将旧候选的刷入结果视为新构建的实机证明。原厂镜像、设备私有配置快照与未脱敏日志不公开发布。
