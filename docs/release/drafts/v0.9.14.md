# v0.9.14 发布日志草稿

供审阅和修改，覆盖 v0.9.13 之后已合入 main 的功能及本轮内存优化。以下正文尚未写入 Wiki，也未冻结为正式发布快照；版本号暂按下一版 v0.9.14 准备。

## v0.9.14

- 优化设备内存占用，减少 MQTT 订阅、联动状态和命令回执的常驻开销。相对本轮内存优化前的 main，A1 应用静态 RAM 减少约 10.8 KiB，TC1 减少约 1.0 KiB；这些数值不包含运行时动态内存。
- A1、M1 的设备联动上限统一为 4 台。升级后，原有超过 4 台的联动配置仅启用前 4 台；这里限制的是联动对象数量。
- HTTP 和 MQTT 命令按实际内存余量申请资源，内存忙时等待或返回 busy；优化 MQTT 回执排队和发送顺序，减少高负载下的回包超时。本地网页按顺序发送命令，降低页面初始化时的并发压力。
- 增加内存余量、分配失败和回执队列诊断，便于排查繁忙及资源不足问题；保留 Wi-Fi、MQTT、定时、按键、自动控制等已有设置。
- 压缩三款设备的内置网页资源，保留原有页面功能、中英文及交互。
- 提供完整版和 `no-frontend-resources` 精简版固件。精简版保留离线配网、首次 MQTT 配置和网页密码设置，日常控制及完整设置通过本地设备管理页面或 IotCloud 使用；在线升级保持当前固件类型。
- 新增无需账号、后端或 Broker 的本地设备管理入口，填写设备内网 IP 和网页管理密码即可直连。浏览器需允许访问本地网络；普通管理平台也可配置内网直连，探测失败时继续使用 MQTT。

### 验证与已知限制

- 本轮最终内存优化候选已在 A1、TC1 完成签名升级、配置核对和只读压力测试。800 条 MQTT 请求均收到成功或 busy，两款各 10 轮撤压后受监控内存和队列均归零，测试期间未观察到重启。M1 的最终实机验证由其他测试线程负责，不计入这里的结论。
- A1 压测仍出现 3 次 HTTP 连接重置，尚未达到所有请求都成功或受控 busy 的目标。当前连接及紧急回执仍有资源边界，任意并发、长期零泄漏或全系统零 OOM 尚未得到证明。
