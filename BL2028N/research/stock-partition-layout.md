# S30-V1B 统一原厂分区与双向切换可行性

2026-10-30 更新：**原厂分区适配已作为显式实验模式构建，原厂 → 社区网络 OTA 及后续社区 OTA 已实机通过**；原厂 bootloader 与工厂 MAC/RF 完整保留。详细实测见[实机记录](stock-ota-live-test.md)。双向免拆 OTA 仍未验证。

用户随后将目标缩小为“原厂单向免拆安装社区固件”，不要求刷回原厂。本报告保留布局研究结果，但双向切换、原厂恢复包和原厂完整生命周期的尾部写入审计不再作为该单向目标的验收前置条件。社区仍须适配保留的原厂启动器与 OTA 边界；当前执行范围及单向验收见[原厂 OTA 研究](stock-ota.md#当前目标原厂单向免拆安装社区固件)。

适用对象仅为已双读备份的 S30-V1B / BL2028N / BK7231N、原厂应用 `2M.1220`。最终实物为 `1.0.0-rc.3-dc3a36-dirty`、本机原厂启动器；软件重启进入 BootROM、只读回读及重启恢复均已重新验证。下文布局比较、容量、迁移和双向步骤保留的是此前离线研究；“当前社区版”列特指迁移前的上游启动器布局，不能当成最新实物状态。

## 实际布局差异

地址区间均左闭右开，未注明时为物理 Flash 地址。

| 区域 | 本机原厂 | 当前社区版 | 统一时的处理 |
| --- | --- | --- | --- |
| 启动区与保留空隙 | `0x000000–0x011000` | 相同起止，内容为上游 bootloader | 保留本机原厂 bootloader，不随应用 OTA 改写 |
| 应用存储区 | `0x011000–0x132000` | 实际镜像结束于 `0x129F70`，随后到 OTA 起点留空 | 使用原厂应用边界、CRC 编码与尾块位置 |
| 应用尾块 | `0x131F9A–0x132000` | `0x129F0A–0x129F70` | 打包器和启动器必须使用同一位置 |
| OTA / download | `0x132000–0x1E0000`，696 KiB | `0x12A000–0x1D0000`，664 KiB；另与 LittleFS 共用空间 | 下载、容量校验、失败清理统一到原厂区域 |
| RF / 工厂 TLV | `0x1E0000–0x1E1000` | 已适配到原厂地址 | 原样保留实际 MAC 和射频数据 |
| 原厂 NET info | `0x1E1000–0x1E2000` | 不作为社区配置使用 | 保留，不能假定原厂配置格式等于社区格式 |
| 社区原生 CFG | 原厂 OTA 区内，无独立分配 | `0x1D1000–0x1D2000` | 必须迁出 OTA 区 |
| 社区 LittleFS | 原厂 OTA 区内，无独立分配 | 默认 `0x1C8000–0x1D0000`，32 KiB | 必须迁出 OTA 区，禁止依赖当前包恰好较小 |
| 社区 EasyFlash | 本机原厂备份对应区域为空 | `0x1E5000–0x1ED000`，32 KiB | 保留，与原厂 EasyFlash 分开 |
| 原厂 EasyFlash | `0x1FE000–0x200000`，8 KiB | 原厂数据尚在 | 保留，社区不得在这里初始化自己的环境库 |

原厂 bootloader 三个 `01PE` 描述符的 CRC32 均已复核：`download` 为 `beken_onchip`，其地址是原始物理地址；`app` / `bootloader` 为 `beken_onchip_crc`，使用逻辑地址。原厂 app 的 `start=0x10000, size=0x110000` 是正确值，转换为 32+2 字节存储后正好对应物理 `0x11000–0x132000`。不能把它改为原厂应用 SDK 表中的 `size=0x143000`，后者与 OTA 区重叠。

## 已完成的容量与校验验证

| 项目 | 原厂恢复应用 | 新社区候选 |
| --- | --- | --- |
| 应用版本 | `2M.1220` | `1.0.0-rc.3-dc3a36` |
| 纯应用大小 | 962047 B | 664576 B |
| GZip + AES256 RBL | 649504 B | 476320 B |
| 按 4 KiB 擦除向上取整 | 651264 B | 479232 B |
| 放入原厂 712704 B 下载区 | 通过，剩余 61440 B | 通过，剩余 233472 B |
| 原厂 `0x9B74` 自定义校验 | 13 个正常/边界/错误输入用例通过 | 同样 13 个用例通过 |
| 包的 CRC32 / FNV / 解密 / 解压 | 通过，解出应用与原厂 Flash 原文逐字节相同 | 通过 |

原厂恢复包由本机备份重打包，仅保存在私有运行目录；不把包含厂商数据的包放入 Git 或公共发布。该包不是下载到的官方 OTA，表中通过项不代表原厂启动器已经实际解密、安装并启动它。

当前社区版扣除默认 LittleFS 后，下载上限为 `0x1C8000-0x12A000=647168 B`（632 KiB）。原厂恢复包按扇区取整后超过上限 4096 B，现有保护应拒绝。离线擦写回放证明：去掉保护直接写会破坏 LittleFS；只把起点改成 `0x132000`、仍保留旧配置地址，也会破坏 LittleFS。禁止只修改 OTA 起点或放宽长度检查。

## 建议的社区数据位置

保留全部原厂区域，在原厂主分区表之外的尾部保留区增加社区私有数据：

| 数据 | 候选物理区间 | 大小 |
| --- | --- | --- |
| 社区原生 CFG | `0x1E2000–0x1E3000` | 4 KiB |
| 社区 EasyFlash | 保持 `0x1E5000–0x1ED000` | 32 KiB |
| 社区 LittleFS | `0x1F0000–0x1F8000` | 32 KiB |
| 原厂 EasyFlash | 保持 `0x1FE000–0x200000` | 8 KiB |

候选 CFG / LittleFS 区域在原厂备份与当前社区整片回读中均为空。内存模型已复制现有 CFG / LittleFS 到候选地址，再分别写入两种完整 RBL，以及写满整个 696 KiB download 分区，原厂启动区、RF、NET info、两套 EasyFlash 和迁移后的社区配置均未变化。**这是地址隔离验证；还需跟踪原厂完整生命周期的写入范围，才能把这些尾部位置定为正式约定。** 空白快照不等于所有工作模式都不会使用它。

配置迁移应采用一次性流程：检测来源布局及格式/校验 → 保存两套旧数据 → 写新位置 → 读回校验 → 持久化完成标志 → 启用新 OTA。迁移未完成时应拒绝会覆盖旧数据的升级，不能每次启动都从旧地址恢复；旧地址之后可能已经是下载包。切回原厂应保留原厂自己的环境区；两套设置不直接互相解释。若配置无法保留，可以沿用用户已接受的重新配网，但工厂 RF/MAC 不能删除。

## 可以实现的切换与尚缺的证据

采用同一原厂 bootloader 和应用边界后，切换方式是把目标系统的 RBL 放入同一 download 区，由启动器覆盖安装到 app 区。此方案只有一个运行应用槽，不能仅靠统一分区实现开机菜单式双启动。原厂 bootloader 已观察到按 96 字节头差异决定升级，未看到版本大小顺序比较，但完整启动流程仍需验证。

| 路径 | 方案 | 当前验证程度 |
| --- | --- | --- |
| 原厂 → 社区 | 原厂网络入口下载社区 RBL，保留原厂 bootloader | 静态调用链与自定义校验通过；网络入口可达性和安装启动未实测 |
| 社区 → 原厂 | 社区 WebUI 提供本机恢复包 URL，使用同一原厂 download 区 | 包重打包、完整性与容量通过；实机安装未测 |
| 社区 → 社区 | 同一 download 区写入新版本 RBL | 当前旧分区已有历史记录；新布局尚未刷入 |
| 当前已换上游启动器的设备 → 统一布局 | 完整备份后，一次串口迁移启动器与应用，保留工厂与两套数据 | 尚未执行；仅更新应用不能改变旧启动器的固定分区 |

**统一布局解决存储和启动契约，不会自动打通原厂的升级控制入口。** 在原厂本地 OTA 入口仍未证明可用的情况下，不能承诺任何时候都能无拆机返回社区。正常切换也不具备两个完整应用槽的自动故障回退能力。

## 实施与实机验收顺序

1. 先完成原厂启动器解密、解压、写应用及尾块重建的完整仿真；现有 13 用例只执行自定义校验函数。
2. 将布局定义集中到一份来源，配套修改 SDK 分区、原生 HTTP OTA、LittleFS、CFG、打包器、容量检查、失败清理和串口刷写校验。原厂 SDK 中的重叠声明不照抄。
3. 完成旧布局数据的一次性迁移与断电恢复回归，锁定原厂尾部写入范围。
4. 重新证明本机串口恢复可用、双读备份一致，再刷入保留原厂 bootloader 的统一布局实验固件。
5. 实测原厂 → 社区 → 原厂 → 社区；每次核对运行版本、计量/继电器/按键、工厂 MAC/RF、Wi-Fi 恢复、两套配置及整个保留区。另测包损坏、超容量、下载中断和安装期间断电恢复边界。

本轮没有修改生产分区或刷写启动区。已安装设备仍使用旧布局，不能把本报告的候选地址当成已经部署的布局。

以上是实机前的实施计划。本机随后已通过完整原厂恢复建立基线，由原厂网络入口实际安装实验布局，并完成后续社区 OTA；两次 OTA 均保留原厂启动器。旧社区布局配置搬迁和双向切换不在本次验收内，生产默认构建也没有改为本实验布局。请以[实机记录](stock-ota-live-test.md)和独立实物 JSON 为准，不改变下列离线回放 JSON 的含义。
