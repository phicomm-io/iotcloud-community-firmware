# A1 硬件控制依据

依据为 [a2633063/zA1 v0.3.1](https://github.com/a2633063/zA1/releases/tag/v0.3.1) 的 `zA1@MK3080B@moc.ota.bin` 与 ALL 包静态分析。上游仓库没有应用 C 源码；[Wiki 通信协议](https://github.com/a2633063/zA1/wiki/通信协议) 是旧 App/UDP 层协议，并非 GPIO/I²C 原理图。本应用按以下观测独立实现，不复制上游机器码。

分析时仓库提交：`f4f67ee88d9287fd1badff55ccd7704bb0f748c4`，Wiki 提交：`685fb9c07c223f88677f94c37c5d49555ca2ce95`。

| 输入 | 字节数 | SHA256 |
| --- | ---: | --- |
| OTA | 622664 | `eccfaddfafbaae65d6bcfdf431caef45f677b558c34636882e28e71a923e8ae3` |
| ALL | 1077968 | `322e8016bef929871e9d57caa32a5b99ce090c360ec99cb1f5bee6429ef75dc8` |

OTA 是 ALL 中 `0x13000` 起的区域，OTA 前 `0x75000` 为 MiCO 内核及填充，SHA256 为 `f22ad344286bb97755ab7ba2fb18e8768140c5383875098dfb0449d2184abc74`，与所选 SDK 3.6.4 的 MK3080B 内核一致。应用头 CPU 地址 `0x08088000`，ABI 3。

## GPIO / 外设

| 物理 GPIO | SDK 名称 / 枚举值 | 作用 |
| --- | --- | --- |
| 19 | `MICO_GPIO_19` / 9 | 风机使能，低有效；输出开漏无内部上拉，关闭为高 |
| 12 | `MICO_GPIO_12` / 6；`MICO_PWM_3` / 2 | 风机 PWM，1000Hz；初始化为推挽高 |
| 13 | `MICO_GPIO_13` / 7 | 灯环单线数据，推挽；GPIO 数据寄存器 `0x40001000` 位 `0x1000` |
| 7 | `MICO_GPIO_7` / 2 | I²C1 SCL |
| 8 | `MICO_GPIO_8` / 3 | I²C1 SDA |
| 14 | `MICO_GPIO_14` / 8 | 观测到初始化为上拉输入，用途未确定，保持输入 |
| 21 / 22 | `MICO_GPIO_21` / 10、`MICO_GPIO_22` / 11 | UART2 调试 TX/RX，115200 |

SDK 通用板代码将 GPIO19 当作系统状态灯、GPIO23 当作配网按钮，与 A1 不符。`sdk.patch` 禁用这些通用回调，在内核 GPIO 初始化表中为 GPIO19 配置上拉输入，再于应用平台初始化时先写高、设置开漏输出；GPIO12 先写高、设置推挽输出。此后由单一硬件线程拥有风机和灯环 GPIO。

## 风机

上游初始化函数 `0x0808D8E8`，目标设置 `0x0808D970`，约 100ms 回调 `0x0808D858`：

- speed ≤ 0：GPIO19 高、停止 PWM、当前逻辑速度清零。
- speed 1～100：目标截断至 100，每次调整当前逻辑速度最多 10 个点。
- `PWM3`：1000Hz，占空比百分数 `80.0 - 0.6 × 当前逻辑速度`，启动后 GPIO19 拉低。
- 没有识别到 RPM 反馈；不能把逻辑百分比作为测量转速。

本实现约 100ms 更新 PWM，面板约 40ms 轮询。PWM API 失败时拉高风机使能并停止输出，记录诊断；再次按当前目标尝试。

## 触摸面板

上游 `0x0808A2F0` 使用 I²C1、7 位地址 **0x08**、标准 100kHz。设备结构在 `0x080AAE64` / RAM `0x1003010C` 可见六字节 `00 00 08 00 00 01`。初始化后 Probe 重试数 2；读取使用一个 combined message：TX `00` 一字节，RX 三字节，重试数 5。

按优先级解码：

1. RX[1] = 1：电源键。
2. 否则 RX[2] = 1：Wi-Fi 键。
3. 否则 RX[0] ≤ 99：触摸位置；0 为无有效滑动事件。

电源键只处理按下边沿；连续有效非零位置的差值增减风速，限制 1～100%，不是把位置直接当风速。错误回包清除上一键/位置状态并计数，不伪造输入。Wi-Fi 连续按下 2.5 秒触发 AP，每次按住只触发一次。

## 灯环

上游 RAM 函数入口 `0x10030000`。MK3080B MCU 为 125MHz；帧是 32 个 uint32 槽，颜色打包 `0xGGRRBB`，按内存低三字节 **B、R、G** 发送，每字节 MSB first。

观测到 GPIO 高电平循环：位 1 写寄存器 8 次、位 0 写 2 次，随后低电平写 6 次。槽 0 后有低电平循环 10000 次，再发槽 1～31。不能由此直接断言 32 个物理 LED，也不把槽 0 明确命名为某一种物理元件。

本实现使用 `.fast` SRAM 段、GCC `optimize("O0")` 的固定循环，发送中保存/恢复 PRIMASK，保持其余 GPIO 位，末尾增加低电平锁存间隔。ELF 可确认代码及寄存器地址常量位于 SRAM，没有在屏蔽中断段调用 Flash 函数。高/低循环仍需逻辑分析仪验证，不从二进制推算未经测量的纳秒时序。

速度条长度 `min(31, floor(speed/3)+1)`，索引从 27 开始递减、在 1 后回绕 31。索引 27 为 Wi-Fi 状态覆盖位置，连接显示蓝、未连接或 AP 显示红。自定义 RGB 用于其余亮起的速度条；关闭风机时整圈显示所选 RGB。自动熄灭隐藏整帧。
