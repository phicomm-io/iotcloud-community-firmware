# M1 空气检测仪

## 功能

- 温度、湿度、PM2.5 和甲醛读数；每 5 秒查询，15 秒无新读数标记失效。
- 原屏幕亮度 0–4、NTP 校时与时区设置。
- 获取 Wi-Fi IP 后立即校时，成功后每小时校时，失败后每 60 秒重试；重连、修改时区或 NTP 地址会立即重新校时，OTA/待重启期间暂停。先尝试 WebUI「设备」中设置的首选 NTP 服务器（域名或 IPv4，最多 63 字节），失败后依次尝试 `ntp1.aliyun.com`、`time1.cloud.tencent.com`、`cn.ntp.org.cn`、`pool.ntp.org`、`cn.pool.ntp.org`，跳过重复地址。首个有效响应用于更新软件时钟并向屏幕下发时间；设置持久化，不改变原配置布局。串口日志记录来源和结果；屏幕入队成功不代表已收到屏幕确认。
- 中文离线 WebUI、Wi-Fi 扫描与配网、MQTT / Home Assistant 自动发现、网页管理密码。
- 与一台或多台 A1 净化器绑定，配置联动、灯效、定时与睡眠；优先局域网通信，超时回退 MQTT。
- 参数持久化、本地文件与 HTTP 直链 OTA。
- MQTT 接收先检查 socket 可读状态，遵守 MQTT 等待期限；空闲超时不视为断线。

适用于原装 EMW3080B / MK3080B（MX1290）Wi-Fi 模块，保留 ATSAMD20 传感器和屏幕控制器，不适用于 ESP32 转接方案。

关键业务线程由硬件看门狗保护；诊断页显示复位原因，若上次因看门狗超时重启会明确提示。断网和传感器暂无数据不会单独触发重启。详见[看门狗机制与验证](../docs/watchdog.md)。

## 构建方法

Linux x86_64，推荐 Ubuntu 22.04。安装 `build-essential bzip2 curl git perl python3 zlib1g-dev libncurses5 libtinfo5`，在仓库根目录执行：

```sh
./M1/build.sh
```

脚本下载固定提交的 MiCO 3.6.4 SDK、ARM GCC 5.4.1 和 Python 2.7.18，构建 `M1@MK3080B@moc`。SDK 提交为 `6c465211d3ff8797cd835e400ec54a06530dd476`。可用绝对路径 `M1_SDK_DIR`、`M1_TOOLS_DIR`、`M1_PYTHON2` 指定依赖；SDK checkout 不要与 A1 共用。

产物在 `build/m1-release/`：`phicomm_m1.ota.bin`、`phicomm_m1.all.bin`、应用及 ELF/MAP、`manifest.json`、`SHA256SUMS`。网页升级只选 `.ota.bin`，完整镜像不作为通用首刷包。

## 使用方法

首次连接 `M1-AP-<MAC后六位>` 热点，访问 `http://192.168.0.1/` 配置 Wi-Fi。连接失败约 60 秒后恢复热点；联网后通过路由器查询设备 DHCP 地址。

填写 MQTT Broker 后，HA 可自动发现四个传感器和亮度实体。原生主题根为 `phicomm/m1/<12位小写MAC>`：`sensor` 提供非保留 JSON 读数，`brightness/set` 接收非保留单字符 `0`–`4`。网页可设置设备名、屏幕亮度、时间与时区。

「绑定与联动」中填写 A1 的 MAC，可设置局域网 IP、强制 MQTT 或恢复探测。其他配置页操作绑定列表的第一个 A1；组目标使用在线协调者。绑定后 HA 使用逻辑设备，原主题仍可控制和读取。详见 [绑定联动配置](../common/README.md)。

网页密码默认关闭；启用后用户名为 `admin`，密码最多 32 字节。Wi-Fi 和 MQTT 密码留空保留原值。网页和 MQTT 为明文连接，请在可信网络使用。

WebUI 首页显示实时传感器数据、数据更新时间、连接状态及屏幕亮度。进入「设置」后，通过二级菜单访问 Wi-Fi、MQTT / HA、设备、绑定与联动、固件升级及诊断；切换页面不会清空未保存的输入。

诊断页将 JSON 解析为设备、网络、MQTT、传感器、串口、时间同步及升级状态，显示最近校时源、成功时间（UTC）和重试倒计时，保留可折叠的原始 JSON；绑定传输状态同样按字段展示。`GET/POST /ntp/config` 管理本机首选服务器，POST 示例 `{"ntp_host":"ntp1.aliyun.com"}`；`/time/config` 管理本机时区，绑定设备的时钟设置使用 `/binding/time/config`。

### 实体按钮支持范围

- 短按：原屏幕控制器处理屏幕亮灭，Wi-Fi 模块接收 `0x0f` 通知并同步亮度状态；已由用户确认实机正常。
- 按键重启、恢复出厂、重置网络：当前固件没有实现对应处理，不能将长按视为已支持。SDK 通用开发板 GPIO23 按钮初始化已禁用，不能直接套用开发板的长按逻辑。
- 网页「重启设备」只执行重启，不清除设置。Wi-Fi 断线约 60 秒后开启配网热点也不等于清除 Wi-Fi 配置。

增加实体长按功能前，需要确认原屏幕控制器是否上报长按事件及其 UART 帧，或取得按键实际接线证据；当前不能仅从短按通知推断长按时长或重置指令。

### 甲醛与 PM2.5 彩色指示灯

当前 Wi-Fi 模块固件及所核对的参考驱动只提供传感器查询、整体屏幕亮度和时间命令，尚无已验证的独立颜色或阈值设置命令。因此暂不提供声称能控制实物灯的配置入口；A1 绑定灯带的颜色设置不代表 M1 原屏幕指示灯可控。要实现自动阈值和手动颜色，仍需确认 ATSAMD20 屏幕控制器的相应协议，或实际灯驱动接线。

### Wi-Fi 错误指示灯

异常标志使用 PWM4（GPIO13），Wi-Fi 图标使用 PWM5（GPIO14）。该对应关系依据实机正常联网时的图标观察修正；SDK 只能证明 PWM 与 GPIO 的对应关系，不能证明屏幕图标接线。异常标志按以下优先级显示网络状态：

| 状态 | 灯效 |
| --- | --- |
| 未保存 Wi-Fi SSID | 亮 500 ms、灭 500 ms 循环 |
| 已配置 Wi-Fi，但未连接或已断开 | Wi-Fi 图标与异常标志同步亮 500 ms、灭 500 ms |
| Wi-Fi 已连接，MQTT 已配置但未就绪（包括认证或 ACL 失败） | Wi-Fi 图标常亮，仅异常标志两长两短循环 |
| Wi-Fi 已连接，MQTT 未配置或已就绪 | 熄灭 |

两长两短的周期为 3.6 秒：亮 800、灭 200、亮 800、灭 200、亮 200、灭 200、亮 200、灭 1000 ms。状态变化时从新灯效的起点开始，不阻塞 UART 传感器通信。指示灯亮度沿用现有屏幕亮度对应的 PWM 占空比；PWM5（GPIO14）控制 Wi-Fi 图标：Wi-Fi 已连接时常亮；未连接时随异常标志的亮相同时亮起；PWM4 控制异常标志，按上表显示。熄灭时将对应引脚切换为推挽低电平，避免停止 PWM 后输出电平不确定。用户已在 OTA 后确认正常连接时 Wi-Fi 常亮、异常标志熄灭；故障闪烁时序由主机测试覆盖，故障状态的实物显示尚未逐项验证。

OTA 选择 `phicomm_m1.ota.bin`；HTTP URL 必须是直接文件地址，不支持 HTTPS、重定向或分块传输。首次安装和恢复限制见 [Wiki：M1 刷机](https://github.com/phicomm-io/phicomm-community-firmware/wiki/M1-刷机)（接线与供电的通用要求见 [刷机前准备](https://github.com/phicomm-io/phicomm-community-firmware/wiki/刷机前准备)）。
